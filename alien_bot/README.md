# んきー。んきー。星人

このフォルダは **seiha-bot とは独立したDiscord Bot** のコードです。Renderの同じWeb Serviceで動作しますが、Discordアプリ・トークン・スラッシュコマンドは別です。

## Renderの環境変数

- `ALIEN_DISCORD_TOKEN` : 「んきー。んきー。星人」のBotトークン（既存の `DISCORD_TOKEN` は変更しない）
- `ALIEN_GUILD_ID` : 「んきー。んきー。帝国」のサーバーID

**この2つを両方設定するまで、星人Botは起動しません。既存seiha-botの起動はそのままです。** これらの値はRenderの Environment に入力し、GitHubには絶対に書かないでください。

Discord Developer Portalで星人Botを対象サーバーにインストールし、`applications.commands` スコープを有効にしてください。

## 機能追加

`alien_bot/cogs/` に `setup(bot)` を備えたCogモジュールを追加すると、次回起動時に自動読込されます。既存の `cogs/` フォルダは **seiha-bot専用** なので編集不要です。

## 動作確認

RenderのLogsで `[Alien] ログイン成功` と `[Alien] スラッシュコマンドの同期完了` を確認し、帝国サーバーで `/test` を実行すると `test` と返信します。

既存cron-job.orgの定期アクセス先URLおよびRender Start Command（`python main.py`）は変更不要です。

## サーバー管理（第1段階）

設定を有効にすると、このBotは対象Discordサーバーの **Bot・管理者ロール所持者以外** に対して次の処理を行います。

- タスクカテゴリ (ID: `1561752871530270840`) に本人＋管理者ロール＋Botだけが閲覧できる `〇〇の作業場` を作成します。既存メンバーも初回に処理します。
- 初回のみ4つの通知ロール（配信募集通知、業務連絡通知、その他通知、急募通知）を自動付与します。
- `/notice what:<通知ロール>` は対象サーバーの**全メンバー（管理者を含む）**が、任意のテキストチャンネルで自分のロールを付け外しできます。結果は本人にしか見えません。個人作業場がない管理者も使用可能です。
- ロール設定はMongoDBの `nkii_nkii_alien.notification_preferences` に記録され、再起動でリセットされません。退室時の作業場と設定は削除せず、再参加時に復元します。
- これら4種のロールがメンションされたメッセージの約10%に、利用案内を投稿。投稿した案内は1時間後（削除処理は1分間隔）に削除されます。削除予定はMongoDBに保存されます。
- 管理者ロールID: `1541554412126994594`。既存seiha-bot専用の `cogs/` は変更しません。

### 起動手順（必須）

1. Discord Developer Portal → **んきー。んきー。星人** → Bot → **Privileged Gateway Intents** で `SERVER MEMBERS INTENT` と `MESSAGE CONTENT INTENT` を有効にします。既存seiha-botのアプリではありません。
2. 星人Botに `Manage Roles`・`Manage Channels`・`View Channels`・`Send Messages`・`Read Message History` を許可します。
3. Discordのロール一覧で **星人Botの最高位ロール**を、上記4つの通知ロールより上へ移動します。管理者ロールを上回る必要はありません。
4. Renderの既存サービスの Environment に `ALIEN_SERVER_MANAGEMENT_ENABLED=1` を新しく追加し、保存・デプロイします。既存の `DISCORD_TOKEN`、`MONGO_URL`、`ALIEN_DISCORD_TOKEN`、`ALIEN_GUILD_ID` は変更しません。
5. RenderのLogsで `[Alien/Workspace] 同期終了` を確認し、各協力者の作業場で `/notice` をテストします。

**注意：** `ALIEN_SERVER_MANAGEMENT_ENABLED` を設定しない（または `0` にする）限り、サーバー管理Cogは起動せず、従来の `/test` のみが動作します。DiscordのIntentを有効化する前に `1` にすると星人Bot側の接続が失敗する可能性があります。

Discordカテゴリには最大50チャンネルという制限があります。カテゴリが満杯になった場合はログにエラーを出し、それ以上作成しません。ロール付与やチャンネル作成にはDiscord側の権限が必要です。

**今回のコードは第1段階のみ。** 撮影スコア・ショップ・企画募集は今後別Cogとして追加します。

## 撮影・スコア・ショップ（第2段階）

今回の実装は安全のため **デフォルトOFF** です。起動を確認する際、RenderのEnvironmentに `ALIEN_ECONOMY_ENABLED=1` を追加し、再デプロイしてください。既存の星人Bot・seiha-botの環境変数は変更しません。

### コマンド

- `/zzzadmin_shootstart` : 管理者ロール(ID: `1541554412126994594`)保持者が参加しているVCで撮影開始。星人BotがVCへ入り、ステータスを「撮影中🔴」にし、VC内のBot以外の人（管理者を含む）を記録します。
- `/zzzadmin_shootfinish` : 元のVCからBotが退出し、ステータスを「撮影終了」にして全員を精算。撮影開始後に管理者がVCを退出していても実行できます。1サーバーにつき同時撮影は1件です。
- 撮影中の協力者が退出すると管理者専用チャンネル(ID: `1561759852731175053`)に早退記録の **Yes** ボタンを表示します。Yesを押すと、**実際の退室時刻**までの分数でその人のスコアを付与。押さなければ撮影終了時刻まで計算します。再入室時は未確定の早退確認を取り消します。
- 撮影の途中に入ってきた人は管理者の **Yesを押した時点**で撮影参加者になります。Yesの前に退出した人の確認は無効化します。
- `/score` : 協力者は本人の作業場、管理者はサーバー内の任意のチャンネルで、利用可能スコア・申請中の確保スコア・合計を非公開表示。
- `/shop` : 協力者は本人の作業場、管理者はサーバー内の任意のチャンネルで商品リストを非公開表示。
- `/shop what:商品 how:個数` : 協力者は作業場から、管理者はサーバー内の任意のチャンネルから指定商品の購入申請。所有スコアから利用可能分を一時確保し、管理者専用チャンネルに承認・却下ボタンを送ります。承認時に消費、却下時に返却。
- `/zzzadmin_shoprequests` : 管理者が保留申請を一覧表示。
- `/zzzadmin_shopdecision order_id:... decision:...` : 管理者が申請IDを指定して手動承認・却下（通知失敗時の予備）。

### スコアの計算

1分につき1/60スコア、**小数第3位まで切り上げ**。1分未満の秒は計算しません。

- 1分 → 0.017スコア
- 10分 → 0.167スコア
- 30分 → 0.500スコア
- 60分 → 1.000スコア

値はMongoDBの `nkii_nkii_alien.score_wallets` に整数の千分位で記録します。撮影IDを使って同じ撮影からの二重付与を防ぎます。セッションの途中経過と申請、早退YesはMongoDBへ保存します。

### 必要な権限

Discord上の「んきー。んきー。星人」に、VCへの **接続 (Connect)**、**ボイスチャンネルのステータスを設定 (Set Voice Channel Status)**、場合により **チャンネル管理 (Manage Channels)**、管理者チャンネルの閲覧・送信権限を追加します。ステータス変更用APIは `PUT /channels/{channel.id}/voice-status` を使用します。VCの権限・サーバー設定によってステータス変更だけ失敗する場合はRender Logsに表示します。

### 注意事項

- Renderの再起動中はボイス入退室のイベントを受信できません。開始日時・参加者・確定した早退/途中参加時刻はMongoDBに残りますが、再起動中の実際の入退室までは自動復元できません。再起動時に撮影中だった場合は管理者が状況を確認してください。
- 途中退出してYesを押さずに戻ってきた場合は、退出時間も含めて撮影時間に算入します。
- ロール・チャンネル・Botトークンなどの秘密情報をGitHubへ保存しないでください。
- 稼働後、Renderの `[Memory]` ログで512MB以内に収まっているか再確認してください。

### 管理者のスコア・コマンド仕様

管理者ロール保持者も撮影に参加していた場合はスコアを獲得します。撮影開始時の参加人数・途中参加・早退の確認でも管理者を除外しません。ただしBotアカウントは除外します。管理者には作業場を作成しないため、撮影終了時は管理者向け個人チャンネル通知がなくても `/score` で残高を確認できます。

星人Botの旧 `/admin_*` コマンド4つは、Discord上の表示名のみ `/zzzadmin_*` に変更しました。関数名や管理者権限チェックは変更しません。一般ユーザーの `/score` と `/shop` は引き続き自分の作業場でのみ利用できます。

## 企画募集・タスク通知（第3段階）

新機能はデフォルトOFF。RenderのEnvironmentに **`ALIEN_PROJECTS_ENABLED=1`** を追加して再デプロイすると有効になります。既存のBot設定は変更不要です。

### 管理者コマンド

`/zzzadmin_project` は管理者ロール(ID: `1541554412126994594`)の所持者がサーバー内のどのチャンネルでも実行できます。

Discordの入力フォームで以下のように指定します。

**撮影日時**
```
11/14 13:00 21:00
11/15 13:00 21:00
```

**企画名 | 参加人数**
```
AI（ChatGPT and Gemini） vs 人間 コードネーム対決 | 2
素人ギャンブラー | 3-7
シンプル会話型人狼 | 8-
```

最大10撮影枠、1枠約3時間、`25:00` といった日を跨ぐ時刻にも対応します。日付は `11/14` か `2026/11/14` で指定します。年を省略した場合は次に到来する同月同日を使用します。企画の人数範囲は2人から上限なしまで途切れずに指定してください。1人の場合は自動的に「中止」と表示します。

確認画面で「この内容で募集する」を押した時点で、対象サーバーの管理者・Bot以外の撮影協力者に `@shorts企画募集通知`（ID: `1561755446304317532`）を付与してから、募集チャンネル（ID: `1544209717218508882`）へ投稿し、`1️⃣`〜`🔟` と `❌` のリアクションを追加します。

### 回答と期限

- どれか1つでもリアクションしたメンバーは、その募集に対して「回答済み」と判定します。各時間帯の参加人数による企画決定はBotでは行いません。
- 有効期限は**最初の撮影日付の前日23:59:59（日本時間）**。期限の過ぎた募集は通知ロール保持条件に含めません。
- 複数の募集中の企画がある場合、**どれか1つでも未回答であれば通知ロールを保持**します。全募集に回答すると外れます。
- 全リアクションを解除すれば未回答に戻り、有効な募集があれば再び通知ロールを付けます。
- メンバーがサーバーに参加した場合も、有効な未回答募集があればロールを付けます。ただし、管理者とBotは対象外です。\n- 管理者ロールを持つメンバーには専用通知ロールを付与せず、すでに付いている場合も起動後の同期で取り外します。管理者ロールの付与・解除時も同期します。
- MongoDB `nkii_nkii_alien.project_recruitments` に募集と回答を保存。Render再起動などでイベントを取りこぼしても10分ごとにリアクションの現状を照合します。
- 返信/未返信は参加可否の意思表示だけで、参加人数の自動判定・企画の決定はしません。

### 18時の毎日通知

日本時間18:00に、回答待ちメンバーが1人以上かつ有効な募集がある場合、募集チャンネルに `@shorts企画募集通知` をメンションします。同じ日に複数募集があってもメンション投稿は1回だけです。通知は約1時間後に自動削除します（削除予定はDBに保存）。

### 権限

星人Botには `Server Members Intent`、募集チャンネルの閲覧・送信・リアクション追加・履歴閲覧・**メッセージ管理（通知削除用）**、ロールの管理が必要です。Botの最高位ロールを `@shorts企画募集通知` より上に配置してください。

*注意：* 企画募集は既存の `/notice` で扱う4種類のロールとは別に管理します。Renderを停止した状態では18時の通知も実行されません。管理者の確認画面は10分で期限切れになります。
