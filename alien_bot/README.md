# んきー。んきー。星人

このフォルダは **seiha-bot とは独立したDiscord Bot** のコードです。Renderの同じWeb Serviceで動作しますが、Discordアプリ・トークン・スラッシュコマンドは別です。

## Renderの環境変数

- `ALIEN_DISCORD_TOKEN` : 「んきー。んきー。星人」のBotトークン（既存の `DISCORD_TOKEN` は変更しない）
- `ALIEN_GUILD_ID` : 「んきー。んきー。帝国」のサーバーID

**この2つを両方設定するまで、星人Botは起動しません。既存seiha-botの起動はそのままです。** これらの値はRenderの Environment に入力し、GitHubには絶対に書かないでください。

Discord Developer Portalで星人Botを対象サーバーにインストールし、`applications.commands` スコープを有効にしてください。

## 機能追加

`alien_bot/cogs/` に `setup(bot)` を備えたCogモジュールを追加すると、次回起動時に自動読込されます。既存の `cogs/` フォルダは **seiha-bot専用** なので編集不要です。

## 動作確認

RenderのLogsで `[Alien] ログイン成功` と `[Alien] スラッシュコマンドの同期完了` を確認し、帝国サーバーで `/test` を実行すると `test` と返信します。

既存cron-job.orgの定期アクセス先URLおよびRender Start Command（`python main.py`）は変更不要です。

## サーバー管理（第1段階）

設定を有効にすると、このBotは対象Discordサーバーの **Bot・管理者ロール所持者以外** に対して次の処理を行います。

- タスクカテゴリ (ID: `1561752871530270840`) に本人＋管理者ロール＋Botだけが閲覧できる `〇〇の作業場` を作成します。既存メンバーも初回に処理します。
- 初回のみ4つの通知ロール（配信募集通知、業務連絡通知、その他通知、急募通知）を自動付与します。
- `/notice what:<通知ロール>` は対象サーバーの**全メンバー（管理者を含む）**が、任意のテキストチャンネルで自分のロールを付け外しできます。結果は本人にしか見えません。個人作業場がない管理者も使用可能です。
- ロール設定はMongoDBの `nkii_nkii_alien.notification_preferences` に記録され、再起動でリセットされません。**サーバー退室時に本人の作業場チャンネルを削除**し、再参加時は新しい作業場を作成します。通知設定は保存して再参加時に復元します。
- これら4種のロールがメンションされたメッセージの約10%に、利用案内を投稿。投稿した案内は1時間後（削除処理は1分間隔）に削除されます。削除予定はMongoDBに保存されます。
- 管理者ロールID: `1541554412126994594`。既存seiha-bot専用の `cogs/` は変更しません。

### 起動手順（必須）

1. Discord Developer Portal → **んきー。んきー。星人** → Bot → **Privileged Gateway Intents** で `SERVER MEMBERS INTENT` と `MESSAGE CONTENT INTENT` を有効にします。既存seiha-botのアプリではありません。
2. 星人Botに `Manage Roles`・`Manage Channels`・`View Channels`・`Send Messages`・`Read Message History` を許可します。
3. Discordのロール一覧で **星人Botの最高位ロール**を、上記4つの通知ロールより上へ移動します。管理者ロールを上回る必要はありません。
4. Renderの既存サービスの Environment に `ALIEN_SERVER_MANAGEMENT_ENABLED=1` を新しく追加し、保存・デプロイします。既存の `DISCORD_TOKEN`、`MONGO_URL`、`ALIEN_DISCORD_TOKEN`、`ALIEN_GUILD_ID` は変更しません。
5. RenderのLogsで `[Alien/Workspace] 同期終了` を確認し、各協力者の作業場で `/notice` をテストします。

**注意：** `ALIEN_SERVER_MANAGEMENT_ENABLED` を設定しない（または `0` にする）限り、サーバー管理Cogは起動せず、従来の `/test` のみが動作します。DiscordのIntentを有効化する前に `1` にすると星人Bot側の接続が失敗する可能性があります。

Discordカテゴリには最大50チャンネルという制限があります。カテゴリが満杯になった場合はログにエラーを出し、それ以上作成しません。ロール付与やチャンネル作成にはDiscord側の権限が必要です。

**今回のコードは第1段階のみ。** 撮影スコア・ショップ・企画募集は今後別Cogとして追加します。

### サーバー退室時のログと作業場削除

サーバーのメンバー（管理者・一般メンバー・Botを含む）が退室したら、入室記録チャンネル（ID: `1541546018531708970`）へ「`（そのアカウント名）が退室しました。`」と投稿します（実際は括弧を付けずアカウント名に置換）。

退室者の作業場（カテゴリID: `1561752871530270840`、チャンネルトピック `alien_workspace_owner:<user_id>` によって本人のものだと確認できたチャンネル）をDiscord上から削除し、MongoDBの作業場チャンネル紐付けも消します。**作業場のメッセージ・添付ファイルもDiscord側で削除され、復旧できない可能性があります。** 通知ロールの設定や別途保存した編集プロフィールは維持します。作業場の削除に失敗したときはMongoDBの紐付けを残してログへ記録します。

星人Botにはログチャンネルの閲覧・送信権限と、作業場の **チャンネル管理** 権限が必要です。作業場の削除と退室ログの送信は独立して実施します。

## 撮影・スコア・ショップ（第2段階）

今回の実装は安全のため **デフォルトOFF** です。起動を確認する際、RenderのEnvironmentに `ALIEN_ECONOMY_ENABLED=1` を追加し、再デプロイしてください。既存の星人Bot・seiha-botの環境変数は変更しません。

### コマンド

- `/zzzadmin_shootstart` : 管理者ロール(ID: `1541554412126994594`)保持者が参加しているVCで撮影開始。星人BotがVCへ入り、ステータスを「撮影中🔴」にし、VC内のBot以外の人（管理者を含む）を記録します。
- `/zzzadmin_shootfinish` : VCからBotが退出し、撮影時間を確定します。**この時点ではまだスコアを付与しません。** 画面の「企画名を入力する」ボタンで名前を登録した時点で、撮影企画の作成・スコア付与・お礼通知を実行します。画面を閉じた場合は `/zzzadmin_shootname name` で再開できます。同時撮影は1件です。
- 撮影中の協力者が退出すると管理者専用チャンネル(ID: `1561759852731175053`)に早退記録の **Yes** ボタンを表示します。Yesを押すと、**実際の退室時刻**までの分数を確定し、企画名を登録するまでスコアは付与しません。押さなければ撮影終了時刻まで計算します。再入室時は未確定の早退確認を取り消します。
- 撮影の途中に入ってきた人は管理者の **Yesを押した時点**で撮影参加者になります。Yesの前に退出した人の確認は無効化します。
- `/score` : 協力者は本人の作業場、管理者はサーバー内の任意のチャンネルで、利用可能スコア・申請中の確保スコア・合計を非公開表示。
- `/shop` : 協力者は本人の作業場、管理者はサーバー内の任意のチャンネルで商品リストを非公開表示。
- `/shop what:商品 how:個数` : 協力者は作業場から、管理者はサーバー内の任意のチャンネルから指定商品の購入申請。所有スコアから利用可能分を一時確保し、管理者専用チャンネルに承認・却下ボタンを送ります。承認時に消費、却下時に返却。
- `/zzzadmin_shoprequests` : 管理者が保留申請を一覧表示。
- `/zzzadmin_shopdecision order_id:... decision:...` : 管理者が申請IDを指定して手動承認・却下（通知失敗時の予備）。

### スコアの計算

1分につき1/60スコア、**小数第3位まで切り上げ**。1分未満の秒は計算しません。

- 1分 → 0.017スコア
- 10分 → 0.167スコア
- 30分 → 0.500スコア
- 60分 → 1.000スコア

値はMongoDBの `nkii_nkii_alien.score_wallets` に整数の千分位で記録します。撮影IDを使って同じ撮影からの二重付与を防ぎます。セッションの途中経過と申請、早退YesはMongoDBへ保存します。

### 必要な権限

Discord上の「んきー。んきー。星人」に、VCへの **接続 (Connect)**、**ボイスチャンネルのステータスを設定 (Set Voice Channel Status)**、場合により **チャンネル管理 (Manage Channels)**、管理者チャンネルの閲覧・送信権限を追加します。ステータス変更用APIは `PUT /channels/{channel.id}/voice-status` を使用します。VCの権限・サーバー設定によってステータス変更だけ失敗する場合はRender Logsに表示します。

### 注意事項

- Renderの再起動中はボイス入退室のイベントを受信できません。開始日時・参加者・確定した早退/途中参加時刻はMongoDBに残りますが、再起動中の実際の入退室までは自動復元できません。再起動時に撮影中だった場合は管理者が状況を確認してください。
- 途中退出してYesを押さずに戻ってきた場合は、退出時間も含めて撮影時間に算入します。
- ロール・チャンネル・Botトークンなどの秘密情報をGitHubへ保存しないでください。
- 稼働後、Renderの `[Memory]` ログで512MB以内に収まっているか再確認してください。

### 管理者のスコア・コマンド仕様

管理者ロール保持者も撮影に参加していた場合はスコアを獲得します。撮影開始時の参加人数・途中参加・早退の確認でも管理者を除外しません。ただしBotアカウントは除外します。管理者には作業場を作成しないため、撮影終了時は管理者向け個人チャンネル通知がなくても `/score` で残高を確認できます。

星人Botの旧 `/admin_*` コマンド4つは、Discord上の表示名のみ `/zzzadmin_*` に変更しました。関数名や管理者権限チェックは変更しません。一般ユーザーの `/score` と `/shop` は引き続き自分の作業場でのみ利用できます。

## 企画募集・作業場リマインド（第3段階）

Renderの Environment で `ALIEN_PROJECTS_ENABLED=1` にすると有効です。従来の通知ロール（旧 `@shorts企画募集通知`）は**不要**です。削除済みのロールへアクセスする処理やロール付与は一切行いません。

### 管理者コマンド

`/zzzadmin_project` を管理者が実行すると募集フォームが開きます。開催日時（例: `11/14 13:00 21:00`）と人数別の企画（例: `企画名 | 2`、`企画名 | 3-7`、`企画名 | 8-`）を入力し、確認してから募集チャンネル ID `1544209717218508882` に投稿します。投稿には最大10枠の番号リアクションと❌を付けます。募集投稿時のロールメンションはありません。

### 回答と期限

- 募集メッセージに何か1つでも番号リアクションまたは❌を付けると、その募集については回答済みです。すべて解除すると未回答に戻ります。
- 募集の有効期限は、最初の撮影日前日の23:59:59 JSTまでです。期限切れ・削除された募集は通知対象外です。
- 複数の募集がある場合、それぞれ独立して回答状態を保存します。通知開始済みの募集に1件でも未回答があれば通知が続きます。**未回答の募集が3日未満なら、その募集に対する通知はまだ始まりません。**
- 募集・回答はMongoDBの `nkii_nkii_alien.project_recruitments` に保持され、Botは10分ごとにDiscord上のリアクションを再取得します。

### 18:00 JSTの作業場への通知

**募集を投稿して72時間が経過した後の最初の18時**から、まだ回答していない一般撮影協力者の各自の「〇〇の作業場」に毎日18時に送信します。管理者とBotには送信しません。1人に未回答募集が何件あっても1日1件だけです。

```
@everyone
まだ回答していない企画募集があります！
（企画募集チャンネル #企画募集）にて、まだ確認していない募集メッセージにリアクションしてください。
募集メッセージになんらかのリアクションを行うことでこの通知は停止します。
```

実際のメッセージでは `#企画募集` はDiscordのチャンネルリンク（`<#1544209717218508882>`）で表示します。個人作業場での `@everyone` は本人と管理者の両方への通知を意図しています。投稿は**自動削除しません**。一日一回の送信管理はMongoDBの `project_reminders` に保存します。

### 権限・注意事項

Botには Server Members Intent、募集チャンネルの閲覧・送信・リアクション追加・履歴閲覧、個人作業場での閲覧・送信、**@everyoneメンション**の権限が必要です。作業場はサーバー管理機能（`ALIEN_SERVER_MANAGEMENT_ENABLED=1`）で作成されたものを利用します。

Renderが停止していた時刻の18時通知は遡って投稿しません。次にBotが18時を迎えた際に、まだ募集期間内・公開後72時間以上・未回答という条件を満たしていれば通知します。回答済みの募集について通知を送信しません。

## 編集用プロフィール提出と17時リマインド（第4段階）

**新機能は初期状態で無効です。** Renderで `ALIEN_EDIT_INFO_ENABLED=1` を追加してデプロイすると有効になります。既存Bot・撮影・ショップのコードは変更しません。

- `/edit_info` : 一般の撮影協力者は自分の作業場から、管理者はサーバー内の任意のチャンネルから実行。
  - ① **Color** `#FF88CC` のようなRGB16進数6桁
  - ② **Picture** 画像を1回最大5枚（表情差分も可）。新規画像は**以前の画像に追加**します（保存は累計50枚まで）。
  - ③ **Name** 正式活動名
  - ④ **連携用SNS（任意）** : `YouTube: https://youtube.com/@...`、`TikTok: https://www.tiktok.com/@...`、`X: https://x.com/...` を1行ずつ記入
  - ⑤ **概要欄用SNS（任意／最大3件）** : `YouTube同上`、`TikTok同上`、`X同上`、または `pixiv: https://...` のように1行ずつ
- フォーム上の「必須」は提出してほしい基本情報であり、**1項目以上の部分提出・更新も可能**。入力を省略した項目は既存の保存値を変更しません。3項目（Color/Picture/Name）がそろって初めて提出完了扱いです。
- 写真はDiscordフォームから直接アップロードします。プライバシー保護のため管理者専用チャンネル(ID: `1561759852731175053`)に実ファイルをアーカイブし、MongoDBにメッセージID・ファイル名を保存します。Botが画像本体をRenderの一時ディスクへ保存することはありません。**管理者は保管メッセージを削除しないでください。**
- 提出を受け付けると本人の作業場へ次のメッセージを送信します（管理者には作業場がないのでエフェメラル応答）。
```
提出ありがとうございます！
もし情報の変更・追加などがありましたら、再度/edit_infoで必要項目のみ記入してください。
また、入力内容に問題があった場合はこちらから連絡します。
```

### 管理者向けコマンド

- `/zzzadmin_edit error:任意` : 実行後にDiscordのメンバー選択欄（最大25人）が表示されます。選択された人は「提出をお願いする対象」に登録されます。未提出・未完成の場合は毎日17:00 JSTに作業場へリマインドします。すでに1度以上提出した人に `error` を指定した場合は、**すぐにエラー通知し、その後も再提出されるまで毎日17時に繰り返す**仕様です。エラー文は選択した全員に共通です。
- `/zzzadmin_edit_info` : 実行後、確認したいメンバーを最大25人選択。活動名・イメージカラー・各種SNS・画像の管理者専用アーカイブへのリンクをまとめた `edit_info_report.txt` を本人だけに表示する応答で取得できます。
- 画像やSNS情報を実際の動画投稿システムへ反映する連携、YouTube/TikTokのコラボ招待送信、Xでの自動タグ付けは**未実装**。今回の機能は編集用アカウント情報の収集・保管・確認までです。

### 自動通知の条件

`/zzzadmin_edit` で対象者に設定した人だけに、日本時間 **毎日17:00** に作業場へ通知します。

- Color/Picture/Nameのいずれかが未提出 → 指定の提出依頼文
- `error` を設定されていて再提出前 → 指定のエラー文
- 3項目完成かつエラー解消 → 自動通知を止める
- 再提出（1項目以上の更新） → エラーを解消したものと扱う。不足項目があれば17時の未提出通知は継続

依頼文とエラー文には `@everyone` が入り、作業場の閲覧権限を持つ本人と管理者へ通知されます。Botには「@everyoneメンション」権限が必要です。Discordの通知設定・ミュートの影響は受けます。送信重複を防ぐため送信日もMongoDBに記録します。

### バージョン・制限

Discord.py **2.7以降**の `discord.ui.FileUpload` が必要です。画像保存メッセージと管理者用作業場へのアクセス権限を確認してください。外部投稿・SNS自動招待機能は本機能を追加しただけでは動きません。

## 撮影企画・動画制作ワークフロー（第6段階）

新しい機能の**追加環境変数は不要**です。従来の `ALIEN_ECONOMY_ENABLED=1` を有効にしているBotで、撮影企画管理コマンドも利用できます。Google DriveのOAuth設定・実接続はまだ不要です。企画データはMongoDBの `nkii_nkii_alien.production_plans` に保存します。

### 1. 通常の撮影

1. `/zzzadmin_shootstart` で撮影を開始（既存機能）。
2. `/zzzadmin_shootfinish` で撮影を終了し、参加者と時間を確定。**スコアはまだ付与しない**。
3. 出てきた「企画名を入力する」ボタンから企画名を提出する。または `/zzzadmin_shootname name` を実行する。ここで初めて、早退者を含む撮影協力者に個別の実働時間を元にスコアを付与し、本人の作業場へ下記の形式でお礼メッセージを送る。

```text
🎬【企画名】への撮影協力ありがとうございました！ 69分 → **1.150 スコア** 獲得しました。
```

企画名が未入力のままの場合、次の撮影は開始できません。Render再起動でフォームが閉じられた場合も、`/zzzadmin_shootname` で再開可能です。管理者出演者には作業場がないためDMで通知を試みます。スコアの二重付与は撮影IDごとに防止し、通知が失敗した場合は `/zzzadmin_plan_settle` で再試行できます。

### 2. 記録漏れの撮影を手動追加

`/zzzadmin_planinfo name date hours minutes award_score`（綴りの指定に合わせた `/zzzadin_planinfo` も利用可能）を実行し、Discordユーザー選択画面で1〜25人の出演者を選択します。

- `name`: 企画名。
- `date`: 撮影日（`YYYY-MM-DD`）。
- `hours`, `minutes`: 撮影時間を時・分で入力（合計1分以上）。
- `award_score`: `True` なら参加者全員に同じ撮影時間のスコアを付与、`False` なら付与しない。

録画した企画と異なり、手動追加では出演者ごとの途中参加・早退時刻は不明なので、選択した全員に同じ時間を記録します。誤登録防止のため操作時に一意の企画IDを発行します。企画名は同名可、同名が複数ある場合の操作には**企画ID**を使ってください。

### 3. ステータス管理

| 内部状態 | 表示ステータス | 条件 |
|---|---|---|
| `waiting_assets` | 一部出演者の素材提出待機 | Color・Picture・Nameのいずれかを提出していない出演者がいる |
| `editing` | 編集中 | 全出演者の `/edit_info` の3つの基本情報が揃うと**自動切替** |
| `review` | 書き出し、出演者へチェック | 管理者がDrive動画リンクを登録し出演者の作業場へYes/Noを送信 |
| `posted` | 投稿完了 | 管理者が投稿済みとして確定し、出演者ごとにコラボ依頼リンクを配布 |

すでに登録済みの素材も判定対象です。提出のたびにチェックするほか、30分ごとに未完了企画を再確認します。編集済み企画は管理者がコマンドで次段階へ進めます。管理者の出演者も素材提出の対象です（`/edit_info` は管理者ならどこでも利用可能）。

### 4. コマンド

| コマンド | 用途 |
|---|---|
| `/zzzadmin_planinfo` / `/zzzadin_planinfo` | 記録漏れの撮影を手動追加 |
| `/zzzadmin_plans` | 最新25件の企画名・ID・ステータスを一覧 |
| `/zzzadmin_plan plan` | 企画の参加者・撮影日・時間・確認結果・状態を閲覧 |
| `/zzzadmin_plan_refresh plan` | 出演者素材を再確認し、条件を満たせば「編集中」に移行。Driveフォルダ同期も試みる |
| `/zzzadmin_plan_settle plan` | 撮影IDごとにスコアを重複させずに付与と通知を再試行 |
| `/zzzadmin_plan_review plan drive_url` | 編集完了後、Google Drive上の動画リンクと**Yes/Noボタン**を各出演者の作業場に配布。Noは「修正希望箇所」入力画面へ |
| `/zzzadmin_plan_collab plan member youtube_url tiktok_url x_post_url no_invite` | 出演者ごとにコラボ依頼リンク・告知ポスト等を記録。招待先がない出演者は `no_invite=True` |
| `/zzzadmin_plan_posted plan published_url force` | 全員のYes後に投稿完了へ。出演者ごとの招待リンクを送信。返事が揃わない場合に管理者判断で `force=True` 指定可能 |

`/zzzadmin_plan_review` のNo回答は理由をMongoDBに保存し、管理者専用チャンネルに修正内容を通知します。修正版で再度 `/zzzadmin_plan_review` を実行すると新しい確認ラウンドになり、古いボタンは無効になります。

`/zzzadmin_plan_collab` で登録するリンクは、管理者がYouTube・TikTok等で取得した**実際の招待リンク**です。現時点ではSNSプラットフォームで招待を自動発行する機能ではありません。個別のYouTube／TikTokアカウント情報は引き続き `/edit_info` で提出します。

### 5. Google Driveとの対応

Drive連携が有効なら、作成した企画IDに対応する **03_企画別素材** の関係者限定フォルダを自動で作ります。出演者のGoogleアカウントが管理者によって登録されていれば、本人には閲覧権限のみ付与します。編集担当を追加する場合は、従来の `/zzzadmin_drive_project_access` を使い、同じ企画IDと対象メンバーのGoogleメールを指定して編集権限を与えます。

`/zzzadmin_plan_review` に登録された動画がBot管理のDrive内にある場合、登録済み出演者だけにファイル閲覧権限を付与します。Google OAuthが未設定・動画が手動アップロードでBotから管理できない場合には、**Google Drive側で管理者が出演者ごとに閲覧権限を設定**してください。「リンクを知っている全員」の公開は不要です。

既存の `/zzzadmin_drive_project`、`/zzzadmin_drive_upload` などの手動ファイル管理コマンドも引き続き利用可能ですが、撮影企画は `/zzzadmin_planinfo` や撮影終了後の企画名登録を入口にすると、参加者・ステータス・共有先がまとまります。

## Google Drive連携（第5段階・専用Googleアカウント）

この機能は**デフォルトOFF**です。サーバー専用の無料Googleアカウント（15GBはGoogle各サービスとの共用）をOAuth 2.0で認証し、Botが作成したフォルダ／ファイルだけを操作します。

**権限方針**: 共通素材と利用規約は、管理者がGoogleメールを確認・登録したメンバー全員に閲覧権限を付与します。個人素材はその本人と専用Googleアカウント、企画素材は指定された関係者と専用Googleアカウントのみ。完成動画は管理者が送付先を個別指定します。**「リンクを知っている全員（anyone）」には絶対に設定しません。** Discord IDだけではGoogleアカウントの所有を証明できないため、**Googleメールの本人確認は管理者側で行ってください。** Google未登録のメンバーには共有リンクの閲覧権限がありません。

### 準備：サーバー専用アカウントで認証する

1. [Google Cloud Console](https://console.cloud.google.com/) でGoogle Cloudプロジェクトを作成し、**Google Drive API** を有効化します。
2. OAuth同意画面／Google Auth Platformを設定します。対象はサーバー専用Googleアカウントだけで構いません。**OAuthクライアントの種類「デスクトップアプリ」**を新規作成し、クライアントID・クライアントシークレットを取得します。
3. ローカルPC（Macなど）で `python3 -m pip install google-auth google-auth-oauthlib` を実行し、環境変数 `GOOGLE_DRIVE_CLIENT_ID`、`GOOGLE_DRIVE_CLIENT_SECRET` を設定して `python3 scripts/alien_drive_auth.py` を実行します。ブラウザで**サーバー専用Googleアカウント**にログインし、OAuthの許可を完了してください。
4. 出力されたリフレッシュトークンとID、シークレットを**Render Environmentだけ**に設定します。GitHub、Discord、ChatGPT、ログ、公開URLには貼り付けないでください。
5. **GoogleのOAuth同意画面がExternal / Testingのままだと、リフレッシュトークンは通常7日で失効します。** 継続運用前に公開ステータスとアプリの審査／警告画面を確認してください。機密範囲を抑えるため `drive.file` スコープだけを要求します。
6. Renderの環境変数を設定し、デプロイ後に `/zzzadmin_drive_setup` を実行します。

```dotenv
ALIEN_DRIVE_ENABLED=1
GOOGLE_DRIVE_CLIENT_ID=(OAuthクライアントID)
GOOGLE_DRIVE_CLIENT_SECRET=(OAuthクライアントシークレット)
GOOGLE_DRIVE_REFRESH_TOKEN=(ローカルPCで取得した値)
```

必要な認証情報が揃わない場合、Drive用Cogは起動をスキップします。従来の星人Bot・seiha-botは継続動作します。

### 作成するフォルダ

`/zzzadmin_drive_setup` が、専用Googleアカウントのマイドライブ直下に以下の**Bot所有フォルダ**を作ります。親フォルダ全体にはメンバーを招待しません。

```
んきー。んきー。帝国/
  00_利用規約/         ← 登録済みメンバー全員（閲覧）
  01_共通素材/         ← 登録済みメンバー全員（閲覧）
  02_メンバー素材/

  03_企画別素材/
    <企画ID>_<企画名>/  ← その企画の関係者だけ（閲覧/編集）
  04_完成動画/         ← 管理者のみ（完成ファイル単位で配布）
```

### ファイル受け渡し時の注意点

- **大きな完成動画はGoogle Drive Web画面から直接アップロード**してください。Discordコマンド経由の単一ファイルアップロードはRenderメモリ保護のため20MBまでです。Web画面から直接置いたファイルは `drive.file` 権限のBotから直接共有できない場合があるため、その場合はGoogle Drive画面でファイル単位の閲覧権限を関係者に手動で付けてください。将来、OAuthによるGoogle Pickerなどのファイル指定機能を追加できます。
- **共通素材もGoogle DriveのWeb画面で対象フォルダへ直接置けます。** 関係者には親フォルダの閲覧権限が継承されます。
- Discordから退室した人は、登録Googleメールに対する共通・個人・企画・個別完成動画のアクセス権を解除します。**Driveに保存した立ち絵は削除しません。** OAuth失効やAPIエラーで権限解除に失敗した場合はRenderのログに記録します。権限解除が正常かも時々管理者が確認してください。
- 無料15GBは長編動画の保存量に注意が必要です。不要な動画の整理や、容量不足時の外部ストレージ追加は別途検討します。
- **Googleアカウント単位で共有するため、Discordユーザー名とGoogleのメールアドレスの対応は管理者が確認する必要があります。** 誤登録すると意図しない相手にDriveの共有権限を付与します。
